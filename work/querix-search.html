01 / Independent product engineering

Querix Search

Turning ambiguous customer intent into relevant inventory, with a complete path from catalog preparation to search APIs and product UI.

Role
Creator & engineer
Scope
ETL · search · analytics · frontend
System
Tenant-scoped hybrid retrieval

The problem

A catalog rarely speaks the way a customer does.

Product and classified listings contain inconsistent descriptions, attributes, and categories. Customers arrive with incomplete requirements, spelling mistakes, and natural-language queries. I built Querix Search to connect that intent with relevant, tenant-scoped inventory.

  1. 01Prepare the catalogRead-only source refresh, company adapters, normalization, and validation.
  2. 02Publish safelyParquet artifacts and a validated search-ready database handoff.
  3. 03Interpret the requestExact categories and simple filters take a deterministic path; ambiguous queries take a semantic path.
  4. 04Retrieve & rankpgvector HNSW and persistent BM25, reciprocal-rank fusion, then hosted reranking.
  5. 05Deliver the productCanonical database hydration, cursor pagination, developer docs, and private analytics.

My contribution

From source data to the product surface.

Search & serving

Structured query planning, tenant-scoped filters and API access, hybrid retrieval, ranking, pagination, result caching, and API diagnostics.

Data foundation

Incremental catalog preparation with separate vector and lexical text contracts, content hashes, quality gates, and guarded publication.

Product & analytics

A React and TypeScript website, developer documentation, and separate company and internal analytics experiences with session-based access.

Operational behavior

Serving-path readiness, bounded admission, persistent indexes, and explicit degradation when a retrieval branch or hosted reranker is unavailable.

An engineering decision

Spend model calls where interpretation adds value.

Exact catalog categories with simple stated filters use indexed database lookup. Descriptive or ambiguous requests use embeddings and hybrid retrieval. The routing preserves explicit client filters while avoiding unnecessary model work on straightforward queries.

Three repositories. One search experience.

The ETL prepares retrieval content; the search service owns embedding generation and online ranking; the frontend presents the product and its integration contract. Those responsibilities stay explicit so a pipeline change does not silently become a serving change.
